# World Editor mod

This independent Lua mod implements its editor, blueprint format, selection, rotation, preview plan, paste, and undo behavior itself. It uses ShroudForge's public Lua APIs only for game/runtime access: `runtime.world.cursor.get`, `runtime.world.entity.query_props`, voxel operations, entity operations, asset reads, settings, logging, and export storage. Native engine access stays behind those APIs; the mod has no private loader hook or built-in editor implementation.

While the game window is focused, the World Editor polls **F3–F8**: F3 rotates the active blueprint by 90° around its stored up axis, F4 undo, F5 mark selection corner A/B, F6 reset editor state, F7 paste at the live cursor, and F8 capture, save, and select a blueprint. **F9 remains the Modloader UI shortcut; F10 remains the Debug Console shortcut.** The same actions are available as buttons in the mod settings.

The persistent `.sfbp` format writes `SHROUDFORGE_WORLD_BLUEPRINT_V4` (voxels, prop identity and transform, plus the blueprint's up axis) and loads V1–V3 blueprints; older blueprints default to the Y axis. On paste, item IDs are resolved against the current asset catalog and dispatched through KFC Runtime's profile-backed entity spawn operation. The blueprint stores item identity rather than a build-specific runtime entity address.

Voxel writes are bounded to 65,536 cells, aligned to 8-cell chunk boundaries, executed on the game thread, and checked with native readback. A successful readback confirms voxel data only; collision and save persistence still require separate verification. Entity spawn now waits up to two seconds for a matching `CurrentTransform` + `UsedItem` record before reporting success; the returned queue token still is not an entity handle. A multi-entity paste can partially dispatch if a later operation fails; the mod records its undo data and reports the failure, but the game-side spawn queue does not provide an atomic transaction. Blueprints preserve scale, but paste rejects non-unit scale because the native spawn operation does not accept scale. Prop enumeration filters `UsedItem` entities using current `ItemInfo` placement AABBs; recipes missing from the current game asset catalog make the capture fail rather than silently omit an in-region prop.

Undo reads the target voxels before restoring the saved snapshot and pauses if those cells changed after paste. If a paste or target-prop replacement is partial, its recovery state is retained and F6 will not discard it until F4 undo succeeds. F7 uses the live cursor position for its target. In the Modloader UI (F9), open **World Editor → Live runtime discovery**:

- Set **Blueprint up axis** to X, Y, or Z before capturing. The axis is stored in the blueprint; changing this setting later does not change an already captured or loaded blueprint.
- Set **Initial paste rotation** to 0, 1, 2, or 3 quarter turns (0°, 90°, 180°, 270°), then press **F3** in game to advance the active blueprint by 90° each time. The Modloader's **Rotate blueprint (F3)** button does the same. Rotation cycles through 0°, 90°, 180°, and 270° before returning to 0°; it applies to preview and paste.
- Click **Preview placement plan** to resolve the live cursor target and report the rotated dimensions and counts in the ShroudForge log. This preview is non-destructive, but it is a plan preview only: it does not draw a 3D ghost or show the schematic in the game world.
- Use **Paste voxel region** or F7 only after checking the plan. Those actions write to the world.

You can also mark a target using the cursor buttons. Choose whether to replace or add voxel cells and whether to keep or replace intersecting target props. Replacing target props is refused when their recipe, identity, or unit-scale transform cannot be safely verified. F8 names new persistent captures `capture-1`, `capture-2`, and so on, without replacing an existing export.

The Shroudtopia reference confirms these data paths and ShroudEdit's `WorldApi`/blueprint model. The World Editor's core prop capture, count, and target-prop lookup use the native prop-query API; the separate generic `runtime.ecs.query/read/write` API still exposes only component types resolved by exact build profile or unambiguous live discovery. Cursor decoding, asset-reference byte order, recipe completeness, visual placement, collision, and save persistence still need validation in the running game.
