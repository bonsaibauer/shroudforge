# World Editor for ShroudForge

This Lua mod uses ShroudForge's native, build-profiled cursor hook through `runtime.world.cursor.get`, reflected ECS APIs for live prop candidates, and asset APIs for placement metadata. The cursor hook copies `keen::ecs::ClientCursor` at the verified native instruction and returns a stable snapshot without an ECS scan. Prop candidates come from entities carrying `CurrentTransform` and `UsedItem`; placement metadata is resolved from the current build's `keen::ItemInfo` assets. It captures props whose recipe bounds intersect the selected region and stores their item IDs and transforms with the voxel data.

While the game window is focused, the World Editor polls **F4–F8**: F4 undo, F5 mark selection corner A/B, F6 reset editor state, F7 paste at the live cursor, and F8 capture, save, and select a blueprint. **F9 remains the Modloader UI shortcut; F10 remains the Debug Console shortcut.** The same actions are available as buttons in the mod settings.

The persistent `.sfbp` format writes `SHROUDFORGE_WORLD_BLUEPRINT_V3` (voxels plus prop identity, position, rotation, and scale) and loads V1 voxel-only and V2 prop blueprints. On paste, item IDs are resolved against the current asset catalog and dispatched through KFC Runtime's profile-backed entity spawn operation. The blueprint stores item identity rather than a build-specific runtime entity address.

Voxel writes are bounded to 65,536 cells, aligned to 8-cell chunk boundaries, executed on the game thread, and checked with native readback. A successful readback confirms voxel data only; collision and save persistence still require separate verification. Entity spawn now waits up to two seconds for a matching `CurrentTransform` + `UsedItem` record before reporting success; the returned queue token still is not an entity handle. A multi-entity paste can partially dispatch if a later operation fails; the mod records its undo data and reports the failure, but the game-side spawn queue does not provide an atomic transaction. Blueprints preserve scale, but paste rejects non-unit scale because the native spawn operation does not accept scale. Prop enumeration filters `UsedItem` entities using current `ItemInfo` placement AABBs; recipes missing from the current game asset catalog make the capture fail rather than silently omit an in-region prop.

Undo reads the target voxels before restoring the saved snapshot and pauses if those cells changed after paste. If a paste or target-prop replacement is partial, its recovery state is retained and F6 will not discard it until F4 undo succeeds. F7 uses the live cursor position for its target. Choose whether to replace or add voxel cells, keep or replace intersecting target props, and rotate by 0–3 quarter turns around Y in the settings. Replacing target props is refused when their recipe, identity, or unit-scale transform cannot be safely verified. F8 names new persistent captures `capture-1`, `capture-2`, and so on, without replacing an existing export.

The Shroudtopia reference confirms these data paths and ShroudEdit's `WorldApi`/blueprint model. The ShroudForge integration has been built as code, but cursor decoding, asset-reference byte order, recipe completeness, visual placement, collision, and save persistence still need validation in the running game.
