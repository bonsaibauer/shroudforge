# Add Shared UI Translations

Read the shared repository rules at `.agents/skills/repository/repository-working-rules.md`. Paths below are relative to the repository root.

Read `modules/ui-resources/i18n.tsx`, the source `locales/en-GB.json`, affected consumer components, and `modules/modloader/ui/scripts/check-locales.mjs`.

Add a stable feature-specific key to the source catalog and every maintained locale. The check requires exactly the same key set and order: `locale.name`, then `locale.flag`, followed by the remaining source-catalog keys in source order. Keep values nonempty strings and preserve the exact interpolation placeholder names and multiplicity. `TranslationKey` derives from the source catalog. Use `useI18n().t` in consumers rather than another translator or duplicate text table.

For a new locale, add one catalog with `locale.name` and `locale.flag`, then follow the existing Crowdin configuration and repository localization policy. Catalogs are discovered by `import.meta.glob` and the language menu uses their metadata. Do not add a second locale registration list. The existing legacy `en` selection resolves to `en-GB`.

Flags are generated by `modules/modloader/ui/scripts/generate-flags.mjs` using supported country codes or the existing custom flag convention. Generated files live under `build/ui/modloader-inputs/` and must not be edited manually. Crowdin progress is a build artifact consumed by the notification UI and is separate from translation values.

Run the existing locale check from `modules/modloader/ui/` with `npm run locale:check`. Use the normal frontend build entrypoint when the change also affects bundling or rendering. Report affected keys/locales and any source fallback intentionally retained. Do not rename manifest IDs, Lua setting keys or action IDs as part of translating visible text.
