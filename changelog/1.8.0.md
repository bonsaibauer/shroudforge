Changelog:

- Update: Unify mod page navigation in one tab bar for Information, Dependencies, Settings, and mod-defined setting tabs. Select Settings by default, or the first mod-defined tab when no standard settings groups exist.
- Update: Show the ShroudForge version beside the Modloader label in the sidebar navigation.
- Add: Make long Modloader multi-select settings searchable and filterable, group their choices under category tabs, and let mod setting groups open as tabs. Translate option category names through the existing per-mod locale catalogs. Existing option labels and setting groups remain valid without changes.
- Add: Add a Wiki community news notice with custom SVG artwork, a button that opens the Modloader Wiki tab, and a link to wiki.shroudforge.net.
- Add: Load Modloader Wiki pages and article summaries from the ShroudForge MediaWiki API. Search and article views follow the selected UI language, fall back to English (`en-GB`), and sanitize article HTML. Cache up to twelve recent searches and thirty articles, with a total size cap of 1.5 million characters, and reuse fresh local results until the configured refresh interval expires. The interval defaults to 24 hours and cannot be set below one hour. The Wiki module is enabled by default with 30 results per page and up to 120 results per query. Add toolbar and module-setting actions to open the online Wiki, refresh manually, and clear the local cache, using the existing logging and toast flow. Wiki help banners and links are available in the Modloader.
- Add: Provide a repeatable MediaWiki Translate workflow for ten article groups: Dependencies, DLL Manager, Engine, Game Profile Discovery, Hotkeys, Mod Detection, Modding, Modding Locales, Startup Asset Backups, and Translations. Include 120 PO translation files for the twelve supported target locales (`de-at`, `de-ch`, `de`, `es`, `fr`, `hi`, `it`, `ja`, `nl`, `pl`, `sv`, and `zh`), plus a German ShroudForge quickstart translation. Scripts prepare translations, build page content and a publish manifest, publish missing pages and images without replacing existing article text, import PO files, and verify saved translations and rendered language pages.
- Add: Support setting presets in `extended.mod.json`. A `select`, `radio`, or `segmented` controller applies grouped values in the Modloader and the in-game Mods menu. Editing a member setting switches the controller to its custom value, and saving retains the selected preset. Validate controllers, options, and values against the declared settings in both package loading and the website manifest checker. Add English and German guides.
- Add: Expose `value.camera` in reflected `runtime.world.cursor.get()` snapshots. It contains the local camera position, orientation, field of view, aspect ratio, near and far planes, and orbit distance. It is omitted from legacy snapshots and when the active layout lacks those fields.
- Add: Add `shroudforge.contents.read(params)` for runtime mods. It reads a byte range of a game content, such as the levels of a texture, on a background thread and returns a job that the mod polls in later updates with `job:result()`. Each request is limited to 32 MiB, with at most four outstanding reads per runtime. Larger contents must be split into ranges, and invalid ranges return an error instead of being shortened. Only contents of the game files can be read.
- Fix: Apply startup asset patches under Wine and Proton by releasing the asset session reader before commit and releasing reader and writer handles before rollback. Ignore generated mod `.log` files in the preparation fingerprint so DLL logs do not trigger unnecessary reapplication.
- Add: Let a mod's own DLL register functions for the same mod's Lua code. A DLL loaded through `native-plugin.ini`, a DLL Manager selection, or `loader.runtime.register_dll` may export `ShroudforgeModNativeInit` (C header `modules/mod-runtime/native_bridge/shroudforge_mod_native.h`). Lua calls registered functions with `shroudforge.native.call(name, ...)` and lists them with `shroudforge.native.functions()`. Arguments are nil, booleans, numbers, strings, and buffers, with strings and buffers passed without a copy. A mod reaches only its own functions, with no general access to the game or other mods. DLLs without the export load exactly as before. This API is available starting with ShroudForge 1.8.0.
- Add: Give a mod's DLL read-only access to the local camera and building-cursor sample through `read_local_camera` in native bridge ABI 2. The runtime publishes reflection-derived offsets when it creates the runtime API, so DLL access does not depend on a prior Lua cursor snapshot.
- Add: Add the local player's state flags to reflected cursor snapshots as `value.playerStateMask`, read from the same local `ClientPlayerInput` as the cursor (`data.mask`, flag names such as `IsInMultiToolBuildingMenu`). Unknown set bits retain their numbers as strings. A player who joined a game can now tell the building menu of the hammer, which `PlayerInput.fromClient.mask` holds only in the host's world.
- Add: Let a mod's keybind also match while extra modifiers are held with `shroudforge.input.set_keybind_extra_modifiers(setting_key, modifiers)`, for `is_keybind_down` and `was_keybind_pressed`. With `"Alt"`, a `1` shortcut matches both 1 and Alt+1, so a mod's action keys keep working while another of its shortcuts is held on Alt. Required modifiers remain required, and changing this rule does not replay old key presses.
- Add: Let a mod reserve selected keybinds and the mouse wheel during declared input contexts. The player chooses per device with Modloader padlocks. The mod keeps reading its keys, reads reserved wheel steps through `shroudforge.input.wheel_steps`, and reports each context with `shroudforge.input.set_context`. Context reports expire after one second so stopped mods return the input to the game. Escape, F9, and F10 always reach the game. If the game's Raw Input hook cannot be installed, the API reports the failure and leaves the context inactive rather than claiming input was reserved.
- Update: Reduce game-runtime work by removing redundant `VirtualQuery` calls before guarded component and local-cursor reads. Check the entity table directly instead of querying its memory page on every tick.
- Update: Resolve the registered voxel-grid writer on a worker after the local authority's world accepts writes, so its initial lookup does not block the first build. Keep write checks unchanged and release the worker safely when the game exits.
- Update: Move recurring loader-settings reads and document writes, mod-package revision checks and changed-manifest reads, and runtime and diagnostic status writes off the mods' loop. Loader settings refresh every 250 ms and package revisions every 500 ms. Final status writes still complete on stop.
- Update: Improve the download website with step-by-step ZIP extraction and game-folder installation guidance, a folder layout showing `dbghelp.dll`, `dinput8.dll`, `winmm.dll`, `shroudforge/`, and `mods/`, a copyable common Steam path (`C:\Program Files (x86)\Steam\steamapps\common\Enshrouded`), and a direct Wiki navigation link. Simplify the version selector by removing per-version release counts.
