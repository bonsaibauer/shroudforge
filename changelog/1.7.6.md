Changelog:

- Add: Add a Compatibility area with Mod Detection, DLL Manager, Dependencies, and Engine sections. Status indicators show errors, warnings, and ready states in the sidebar, compatibility tabs, and their pages.
- Update: Mod Detection inventories installed mod folders and reads `mod.json`, `extended.mod.json`, `native-plugin.ini`, `src/mod.lua`, and DLL files without loading DLLs or rewriting the mod folder. An optional tolerant setting ignores unknown top-level manifest fields while continuing to validate fields ShroudForge understands.
- Add: Add a release-managed compatibility profile catalog under `shroudforge/runtime/profiles/mod-profiles`. Profiles match a mod by its `mod.json` ID or folder name, then define in-memory `mod.json` capabilities and `extended.mod.json` metadata, client/server targets, companion-file imports, and ordered DLL loading. Existing capabilities are preserved. Matching does not depend on an exact mod version or DLL hash, and profile metadata does not rewrite installed manifests.
- Add: Include an automatically detected profile for Phoenix1355's Creative Mode. It adds the author's metadata and issue link in memory and loads `creative.dll` as an ordinary library for both client and server. No `mod.json` edit or DirectInput DLL setup is required.
- Remove: Remove the Auto Loot Plus compatibility profile from the release catalog, including its installer import for `dinput8.dll` into that mod's folder.
- Update: Extend DLL Manager for profile-based and manual DLL selections, client/server targets, load order, explicit approval of manual DLLs, and editable filename filters. It also manages the existing `native-plugin.ini`, Lua `runtime.register_dll`, and `dinput8-chain.ini` routes through the shared native loader, routes DirectInput calls to the selected chain provider, and reports load results and failures.
- Update: Keep general mod status on each mod page. The Dependencies section focuses on missing or incompatible requirements and known conflicts. The Engine section reports game, runtime, Mod API, and parser readiness.
- Add: Add a searchable offline Wiki with illustrated, localized guides in German, English, Spanish, and French. Compatibility sections link directly to their related guides, and News and Wiki cross-links open the selected article in the Modloader.
- Add: Support optional `beta` and `englishOnly` flags for every news card and template. The UI displays a **BETA** badge when enabled and uses English text when `englishOnly` is true. The new **Multi DLL Manager** news post uses the badge and includes the Creative Mode image, a Nexus download link, and in-app links to the existing DLL Manager and Mod Detection Wiki articles.
- Update: Add consistent INFO, WARN, ERROR, DEBUG, and TRACE logging for compatibility scans, profile choices, DLL loading, and failures.
- Add: Add dismissal controls for individual toast notifications.
- Fix: Preserve required `extended.mod.json` fields when applying compatibility profile metadata.
- Add: Add SDL3-based keyboard and mouse input for loader and mod shortcuts. Configure shortcuts in shared settings, capture keys or mouse buttons directly in the UI, and detect conflicts before saving. Shortcut controls use a consistent layout across mod entries.
- Add: Let mods declare `keybind` settings and read them with `shroudforge.input.is_keybind_down` and `shroudforge.input.keybind_label`. The Modloader displays each mod's configured bindings, and the World Editor uses its configured shortcuts for its actions.
- Update: Add `shroudforge.input.was_keybind_pressed(settingKey)` for press events. It returns `true` once per mod and setting and retains short taps between runtime updates. Use `is_keybind_down` for actions that should repeat while held. Built-in hotkeys also retain short presses, and saved keybind changes are picked up by the existing configuration polls within one second.
- Breaking: Remove backward-compatible behavior for calls to `shroudforge.input.is_key_down("F1")` through `shroudforge.input.is_key_down("F8")` in ShroudForge 1.7.6. The first call per mod writes a migration message to the mod log, and every call raises a Lua error. Mods must declare a `control: "keybind"` setting, assign it under **Compatibility → Hotkeys**, then use `was_keybind_pressed` for press events or `is_keybind_down` while held.
- Add: Selecting F1 or F12 in the Hotkey Manager writes a compatibility warning to the log. The existing toast mechanism displays that warning. F1 may open Enshrouded's feedback window, and F12 may trigger a Steam screenshot. The assignment remains allowed.
- Add: Add Bavarian, Austrian German, Swiss German, Hindi, Italian, Japanese, Dutch, Polish, Swedish, Chinese, U.S. English, and U.K. English UI translations. Existing `en` selections resolve to U.S. English, while U.K. English supplies the fallback catalog.
- Fix: Hand desktop Modloader launches to an already running game-session UI after checking that the recorded process is active and belongs to the same executable. If the game starts later, the desktop UI hands over when the client appears. Modloader, Debug Console, and World Editor windows stay above the game only while their game view is active, and desktop mode no longer reacts to the in-game toggle shortcut.
- Update: Organize uninstall options into separate Enshrouded restoration, installed-mod removal, and ShroudForge data choices. Mods can be removed independently. Keep data, reset only user settings, and delete all ShroudForge data are mutually exclusive choices. Game-file restoration is disabled unless a verified original backup is available, and the confirmation lists the selected actions and their effects.
- Fix: Improve cleanup when files are locked during updates or uninstall. Identify ShroudForge processes holding release files, request graceful window closure, wait for them to exit, and report unrelated or remaining locks with steps to retry. During a full ShroudForge data purge, close verified ShroudForge processes that still hold purge data after the graceful-close period. Retry transient file operations and clear read-only attributes before removing empty mod directories.
- Update: Propagate Windows bootstrap test failures through the workspace test runner so a failed startup-gate check stops the release build before packaging.
- Add: Add `general.showNativeModMenu` and a localized **Show Mods in the game menu** setting under Settings → General → Appearance. The setting defaults to enabled when no saved preference exists. Explicit saved values continue to control visibility. Its label is available in all 15 supported locales.
- Add: Add an optional **ShroudForge** entry to Enshrouded's main menu. It is drawn with the game's own menu-entry renderer and uses the same text, identity, state flags, hover behavior, and activation result expected by the native UI. The original Settings entry is still drawn with its original descriptor and behavior.
- Update: Discover the menu builder and entry renderer from the loaded executable at game startup. The resolver follows the `mainMenuEntries` string reference through unwind-owned, decoded control flow, validates the renderer's argument and state contract, and identifies the repeated menu navigation paths. It installs only when this structure is uniquely verified. It uses no fixed executable RVA or executable-file hash as a compatibility gate.
- Update: Apply checkbox changes to the running game session through a per-process visibility event. The **ShroudForge** entry appears or disappears on the next menu draw without restarting the game. The native binding itself is installed at game startup, so installing a ShroudForge update requires restarting the game.
- Add: Route activation of **ShroudForge** through the existing Modloader toggle path. The game process signals its session's UI host, which dispatches the same toggle event as the configured shortcut. This opens or closes the existing Modloader window without sending a simulated key press. The bridge is active for the game client, not the desktop UI or dedicated server.
- Add: Expose `shroudforge.ui.toggle_modloader()` to client Lua mods. It signals the same per-game UI event as the native menu entry and configured shortcut. It reports an error if the Windows client bridge or session UI is unavailable.
- Update: Include native menu binding status in runtime diagnostics, with the failure reason, visibility state, discovered menu-call count, installed insertion-call count, draw count, and successful activation count. If discovery is ambiguous or the native UI contract does not match, the menu binding remains unavailable and reports why.
- Update: Change the default Modloader window width to 1290 logical pixels to give translated text, especially Spanish, more room.
- Update: Set the Debug Console's default log refresh interval to one second and its default tail size to 64 KiB per log. Log refresh pauses while the window is hidden or minimized and runs immediately when it becomes visible again. A one-time after-install migration updates these saved settings.
- Add: Expose `runtime.player.name()` to client Lua mods. It returns the cached selected character's UTF-8 name or `nil, reason` when unavailable. The native menu callback captures the name on the first valid selection and when the selection or name descriptor changes. The getter requires an active runtime mod with the runtime capability, but no loaded world. Dedicated Servers return `nil` because they have no local character selection.
- Update: Automatic username mode now uses the active runtime's selected-character cache and uses the configured fallback when no current name is available. It no longer reads the rolling character save or restores a name from a previous game process.
