Changelog:

- Update: Show a mod's link buttons under its name at the top of its page, visible from every tab, instead of inside the Information tab.

- Add: Add a Client/Server target switch to the Modloader and Debug Console. In Server target, show server mod data and mirrored module settings through the existing Modloader pages while keeping general UI preferences local. The Debug Console switches between local logs and server log mirrors.
- Add: Stream `enshrouded_server.log` and `shroudforge-server.log` from the server over the existing Steam Networking Messages service. Send bounded log snapshots and deltas, mirror them locally as `logs/enshrouded_server.log` and `logs/shroudforge-server.log` without replacing client logs, and cap retained data.
- Add: Mirror the server's Modloader module settings in `server-modloader-config.json`. Route server setting changes through the existing validation and persistence code, then return the canonical server values to the UI.
- Add: Show the server's installed mod list and support remote mod activation, declared setting changes, and declared Modloader actions. Server changes require an authenticated admin session.
- Add: Validate server admin sign-in against `userGroups` in `enshrouded_server.json`. The matching group name and password must belong to a group with `canKickBan`, `canAccessInventories`, `canEditWorld`, `canEditBase`, and `canExtendBase` all set to `true`. Keep the peer-bound session token in server memory. The password is sent only to the server for validation and is never returned to the client, saved, or logged.
- Fix: Prevent concurrent clients from silently overwriting server module or mod settings. The server checks the expected revision under its existing installation lock, rejects stale writes, and returns the latest state. Replayed mod action requests do not execute a completed action twice.
- Update: Show the connection state in the existing Modloader mode badge. Desktop stays gray because no runtime connection can be measured. Client mode uses the local runtime heartbeat. Server mode uses the Steam P2P health probe: orange while the service starts, green when confirmed, and red when disconnected or unavailable.
- Update: Reserve Steam P2P channel `65534` for Modloader server mirroring and limit public Lua channels to `0` through `65533`. Channel `65535` remains reserved for Network health checks.
- Docs: Update the server Modloader plan with the implemented group-based authorization, session handling, read/write access, and conflict checks. Update the German and English Lua networking guides with the reserved channel range.
- Docs: Add a Tauri 2 migration plan for Linux and Proton that preserves the existing Windows injection path, module ownership, updater transaction, and release layout.
- Update: Set the repository version to `1.8.1`.

- Update: Tint the sidebar in Server target to distinguish it from Client mode.

The mod restores the patch when disabled or unloaded, and the native runtime also attempts restoration on shutdown. Multiplayer replication and client prediction remain unverified.
